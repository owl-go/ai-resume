# 简历专家产品需求与构建提示词

根据本文构建「简历专家」，一个以会话为入口的求职和简历优化 Web 应用。用户可以上传或粘贴简历，用自然语言描述需求，补充目标岗位，取得可核对、可编辑、可导出的简历和面试材料。产品界面与模型输出使用简体中文。

本文描述用户确认的最新需求。将新增、调整或删除的需求合入对应章节，使本文可以独立用于重建产品。实现与测试证据记在 [简历专家实现记录](resume-expert.md)。

## 1. 会话首页

- 首页直接进入会话工作台。用户可直接输入需求，上传材料，或选择四个快捷指引。桌面使用窄工具栏，顶部提供我的简历、设置和使用指南。手机收起窄栏，保留主要工具和输入。
- 宽屏会话左侧保留消息和输入，右侧打开独立滚动的简历预览。优先展示优化稿，尚无优化稿时直接展示导入或粘贴的简历文本，省略「原始简历」标签及其工具栏。可通过「我的简历」重新打开，也可关闭。窄屏通过入口打开单栏预览，关闭后回到当前会话。
- 编辑提交、生成结果通过校验、经历补充或切换版式后，自动在当前浏览器保存一份最新简历稿及版式。刷新或再次打开同一地址时恢复，并以恢复稿继续优化。恢复时宽屏打开简历预览，窄屏可从「我的简历」打开。会话说明提供清除本地保存的入口，当前页仍可编辑。
- 四个入口依次为「优化我的简历」「帮我找匹配的岗位」「针对职位优化我的简历」「根据简历内容设计样式」。用圆角充分的胶囊按钮，只显示入口名称。按钮按文字宽度排列，窄屏自然换行。
- 会话输入框放在工作区底部，包含输入、上传文件和发送。上传入口只显示无边框的回形针图标，保留「上传文件」可访问名称。输入区省略文件用途下拉框。会话开始后可重新展开快捷指引。输入框下方留白，省略文件类型、大小限制、模型处理说明和示例入口等常驻内容。
- 只显示当前动作所需的文字。入口无需额外说明行，设置、上传失败或使用指南可说明相关操作限制。
- 用户消息气泡直接显示正文，省略可见的「你」标签。
- 「使用指南」提供简短上手步骤和「使用示例数据」。示例为虚构的 4 年 ToB 产品经理转 AI 产品经理的简历和 JD。载入示例后由用户发起分析，走正式模型链路。

## 2. 材料与下一步卡片

- 简历和岗位描述都可直接粘贴，或上传 PDF、Word（.docx），每份最大 8 MB。通过回形针或拖拽上传时，定向任务按当前缺项接收附件。未选定向任务且缺简历时默认作为简历。已有材料且用途不明确时，在会话里选择作为岗位描述或简历，选定后直接读取，只更新选中的材料。会话卡片中的上传动作直接指定文件用途。点击「粘贴 JD」打开岗位描述文本输入，保存后按原文记录。附件随会话展示，可查看、修改或移除。
- 解析使用文档文本层。扫描图片 PDF、旧版 .doc、加密、损坏、超限或没有足够文本的文件应给出对应反馈。用户可以重新上传或粘贴文本。
- 根据当前任务实际保存的材料展示缺项。先上传且未选任务时提供任务选项。已选定向任务且收到简历与 JD 时，从 JD 原文识别唯一明确的岗位名称并直接开始分析。标题缺失或指向多个岗位时只请用户确认岗位名。更换 JD 时重新识别由旧 JD 提取的岗位名，用户明确指定的岗位名优先。已有简历但缺 JD 时提供上传岗位描述、粘贴 JD、先优化通用简历。示例材料通过「开始分析示例」发起任务，也可就地查看或修改已收到的材料。
- 下一步卡片将动作按钮与「或者，输入你的需求」放在一起。点击或用键盘激活选项后立即执行对应动作，材料齐备时直接发起任务，材料不足时进入补充步骤。自定义输入通过卡片内的「发送」提交，支持补材料、改需求和切换任务。点击预设动作仅执行该动作。底部主输入框仍可随时使用。
- 首页和工具栏省略独立的「核对材料」入口。材料编辑跟随当前会话，完成后返回当前任务。更换 JD 或岗位名时，使旧报告失效并保留当前简历稿。

## 3. 四种任务

| 入口 | 执行条件与结果 |
| --- | --- |
| 优化我的简历 | 收到简历即可独立完成通用优化。按用户要求或简历已有定位梳理结构、删减重复、改写经历，返回完整可编辑的简历和简短改动说明。缺简历时提示上传或粘贴。无需补岗位、公司或 JD，无岗位匹配评分。对已有简历稿，按本轮指定的范围修改。 |
| 帮我找匹配的岗位 | 根据简历推荐 3–5 个岗位方向。每项给出匹配经历、可能缺口和搜索词。结果按岗位方向建议呈现，实时招聘列表属于待扩展范围。 |
| 针对职位优化我的简历 | 收到目标岗位名称、完整 JD 和简历底稿后执行定向分析。先补齐缺失项，再用当前底稿按 JD 对照真实经历，输出报告和优化简历。 |
| 根据简历内容设计样式 | 按简历信息密度和用户偏好推荐标准、紧凑或居中标题版式，给出选择理由。已有稿件时应用版式并保留内容，只有原始简历时提取结构并保留原文事实、措辞和顺序。预览、PDF 和 Word 使用所选版式。 |

用户可在会话里继续询问简历、求职和面试问题。已有对应结果时，打开 JD 解析、诊断、匹配分析、经历追问、简历优化、最终简历或面试准备。会话内的导出请求打开简历预览，让用户选择 PDF 或 Word。

用户本轮明确要求通用优化时，即使会话已有 JD 或定向报告，也直接生成通用稿。明确要求对照职位或 JD 时才切到定向优化。用户只补充材料或确认继续时，沿用当前任务。

后续优化以最新保存稿为底稿，包括用户手动修改、局部改写和已纳入简历的经历补充。通用优化、定向优化和追问表达使用当前稿，首次优化使用上传或粘贴的简历。明确提交一份新简历时，以新简历为底稿。生成失败或取消时保留当前稿。

### 优化后的诊断与下一步

- 生成优化稿后，在会话结果下方展示「简历诊断」和由当前材料决定的后续操作。支持匹配岗位、按目标岗位定制和调整版式等已有能力。操作按钮按内容宽度纵向排列。
- 点击「简历诊断」后，模型优先读当前稿，从资深招聘 HR 的视角推断最适合的岗位方向，并给出综合、简历内容、初筛邀约及岗位方向匹配四项 0–100 评分、具体依据和证据缺口。初筛邀约使用判断评分。结果以总分和三个维度卡片呈现。
- 诊断进行中逐段显示「思考摘要」，包含简历证据、岗位方向对比、扣分与证据缺口、修改优先级。内容来自模型给出的可公开判断依据，跟随实际流式输出。开始生成评分报告时更新执行状态，报告完成后可展开回看摘要。
- 报告支持查看修改建议和匹配岗位。诊断下方可展开完整报告、按优先建议优化最弱部分，或按推断方向进入定向流程。修改建议说明应改哪段、如何修改和要补什么证据。按推断方向定制时引导提供相应 JD。

## 4. 定向分析与结果页

- 会话收集目标岗位、JD 和原始简历。模型可结合用户提供的行业、公司类型、求职阶段、突出能力、代表项目、工具和技能、量化数据、需保守表述的边界、篇幅与其他补充信息。材料更新应来自用户实际提供的文字或文件。
- JD 解析展示岗位目标、关键职责、要求、关键词和 5 项核心能力。
- 简历诊断先展示匹配结论和最值得补充的问题，再提供可展开的 0–100 匹配度与 10 个维度评分依据。说明已匹配证据、关键缺口和具体下一步。评分是辅助参考。
- 匹配表按「JD 要求、简历证据、证据强度、是否需要补充、优化建议」排列。证据强度为强、中、弱、无。引用真实原文，缺证据时明确标注。
- 生成 5–10 个针对证据缺口的经历追问。用户补充后生成可写入简历的条目，并更新优化对照和最终简历。编辑回答时使其旧生成条目失效。
- 简历优化展示六项重构策略、原文和优化后表达的对照、改写理由与风险。可查看更简洁、降低夸张、AI 产品证据和 ToB SaaS 证据等规则预览。AI 产品和 ToB SaaS 入口只调整证据排序。
- 最终简历包含姓名、个人信息、求职意向、职业摘要、核心能力、工作经历、项目经历、技能工具、教育背景和可选加分项。支持预览、就地编辑、复制、导出 PDF 或 Word。会话预览也可切换版式、导出 PDF 或 Word，导出内容与预览稿一致。
- 优化稿在个人信息后先展示求职意向和教育背景，再展示职业摘要和经历。明确提供的期望薪资在求职意向中单独一行展示，缺失时省略。编辑与导出沿用该顺序。
- 预览中的简历区块提供「添加改写建议」和「手动编辑」。改写建议在区块内输入，可点击灰底胶囊填入「更详细」「补充证据」「更简洁」「突出成果」「突出技能」，发送后通过会话调用模型，只更新选中的区块。补充证据以已有材料为准，证据缺失时标记待补充。手动编辑支持区块内保存或取消。
- 「项目经历」中的每个项目分别框选并提供改写和编辑，更新单个项目时保留其余项目。项目之间以一个空行分隔，项目内部用单换行。
- 「工作经历」按每段任职分别框选并提供改写和编辑，更新一段任职时保留其他任职。每段以公司、职位和任职时间开头，任职之间以一个空行分隔，同段内部用单换行。
- 页面中的优化稿和 PDF 用浅蓝色高亮量化数据和明确成果，用浅黄色高亮「待补充」「需要补充」标记和待补充证据行。待补充行优先使用黄色。联系方式、日期和求职意向中的数字使用正文样式。编辑与导出保留原文。
- PDF 使用与当前预览一致的章节顺序、姓名和标题样式、公司及项目名称强调、高亮和版式。标准版保持左对齐，紧凑版缩小间距，居中标题版居中展示姓名和联系方式。PDF 按 A4 可打印区域自动换行和分页，保留可搜索、可复制的文字。
- PDF 对姓名、章节标题、公司名和项目名使用轻度加粗，保持层级清晰，中文笔画之间留有可辨间隙。姓名和章节标题保留蓝色下划线，其他文字使用常规字重。
- 面试准备给出 10 个追问，逐项写明准备证据与回答建议，同时指出夸大风险、缺失数据、参考自我介绍和五项进一步补强建议。
- 分析、诊断、匹配、追问、优化、最终简历和面试准备从会话中的结果入口打开。详细结果页保留步骤导航和返回会话入口。

## 5. 模型与事实规则

- 会话、定向分析和追问均调用设置中的真实模型。加载时可取消。遇到超时、未配置、连接失败或无效结果时，显示可理解的提示并保留输入。上游 5xx 提示模型服务暂时不可用，保留材料供用户手动重试。
- 会话请求进行中，在消息下方显示「分析过程」「执行过程」和实时执行时长。模型支持流式输出时，先逐步展示本轮公开分析摘要，再增量展示回复和右侧简历草稿。执行过程依据实际收到的阶段与内容更新，定向任务确认材料后进入生成报告阶段。只有完整校验通过的简历可编辑或导出。完成后保留分析依据、执行步骤与时长。等待输出或上游只返回普通 JSON 时显示当前阶段，失败或取消时清除未完成草稿并保留相应反馈。
- 模型仅以用户已给出的事实为依据，保留个人职责、时间、技能、项目阶段与结果口径。姓名和联系方式缺失时留空。缺证据的内容标记【待确认】或【待补充】。学习原型保留原有阶段，经历改写应指出具体对象、个人动作、交付物及已核实结果。
- 以当前消息为主，结合最近会话和当前简历稿。存在当前稿时，模型请求中的简历底稿使用当前稿。历史消息只用于理解任务。用户粘贴的文本和附件属于资料。服务端校验模型返回的动作、材料、结果和版式，再交给页面。
- 模型地址、名称和密钥在设置中配置，支持测试连接。密钥仅由服务端使用，界面只显示是否配置。原始附件、JD、会话和分析报告只保留在当前页面，刷新后重新开始会话。浏览器恢复最新已保存的简历稿和版式。
- 模型请求由 Node.js 服务端发出。部署环境需要代理访问模型时，通过服务端进程启用代理，并让回环地址直连。连接测试使用与实际生成相同的服务端网络路径。
- 项目内 Markdown 维护 [主提示词](../prompts/resume/main.md)、[系统规则](../prompts/resume/system.md)、[会话](../prompts/resume/chat.md)、[分析](../prompts/resume/analyze.md) 和 [追问](../prompts/resume/refine.md)。开发时请求读取项目文件。生产时主提示词优先使用设置中保存的版本，系统和任务规则继续读取项目文件。设置可载入项目模板、预览变量绑定并保存。

## 6. 视觉与排版

- 采用会话工作台风格。浅灰画布、白色卡片、细边框、窄侧栏和轻量底部输入框。正文使用黑灰，选中态与主要动作使用蓝紫色点缀，配色排除墨绿色。
- 简历专家所有页面正文统一为 12px，界面标题、正文、按钮、标签及表格使用常规字重。主标题桌面为 18px、手机为 17px，小节标题通常为 14px。简历预览的姓名和章节标题加粗并加蓝色下划线，公司名称和项目名称加粗。职位和日期沿用正文样式。
- 快捷指引使用内容宽度的胶囊按钮。会话下一步使用白色步骤卡，卡内包含动作按钮、自定义输入和发送按钮。每条常驻文案应能帮助用户完成当前动作。
- 会话步骤卡和底部输入框同宽，左右边缘对齐。卡片发送按钮、输入正文、附件和上传入口共用左侧内容基线，上传与发送图标在同一水平线上。
- 桌面和手机均可操作。窄屏的胶囊和工具按钮自然换行，表格在自己的容器内滚动。各项输入有可访问名称，选项和提交支持键盘操作。

## 7. 构建与验收

- 使用浏览器页面和 Node.js 服务端。界面、文档解析、模型请求和导出应通过本地可运行的入口串联。原生 HTML、CSS 和 JavaScript 可满足现有规模，PDF/DOCX 在服务端解析与生成。
- 验收首页四个胶囊的内容宽度、手机换行、12px 正文和常规字重。底部输入框只用无边框回形针打开文件选择器，并按会话阶段区分简历和 JD。输入框下方无说明行。
- 验收 PDF 和 Word 导入、附件纠正、补齐 JD 后的完整报告、追问生成、最终简历编辑，以及三种版式的预览和导出。
- RX-13：仅上传或粘贴简历后发送「优化我的简历」，应直接生成可编辑简历，不追问 JD 或岗位，不触发定向分析。会话已有 JD 时可切回通用优化。明确选择「针对职位优化我的简历」时，材料缺失则引导补齐。
- RX-14：上传简历后，在下一步卡片点击「优化我的简历」一次即发起请求，点击「针对职位优化我的简历」一次即进入补充 JD 的步骤。上传、粘贴、编辑和继续选项均可直接点击或用键盘执行。卡片「发送」仅提交非空自定义输入，失败后保留输入。
- RX-17：先点击「优化我的简历」再上传，文件识别成功后自动发起一次优化，不出现继续确认。未选任务时仅上传不会发起优化。导入失败时可重新上传，优化失败时可重试。
- RX-15：延迟模型响应时，用户消息下方立即显示分析过程、执行过程、执行时长和取消按钮。公开摘要、回复、简历草稿增量到达时先于最终结果显示。普通 JSON 响应也可正常完成。定向分析进入报告请求后切换到对应阶段。成功后可展开依据和执行记录，失败或取消后清除部分输出并保留反馈。
- RX-18：预览和 PDF、Word 的求职意向及教育背景均位于经历之前。两个项目分别显示编辑和改写入口，编辑或改写一个项目后另一个项目内容不变。页面中「20%」「120 家」及验收、获奖等成果用浅蓝色高亮，待补充证据行用浅黄色。
- RX-19：右侧预览的不同任职分别显示编辑和改写入口。编辑或改写一段任职后，其余任职、项目和其他字段保持原样。
