## 边界与方案

首页改为简历专家，原招聘页面完整保留于 `/candidate-screening.html`，商品图工作台及其 API 不改变。使用原生 HTML/CSS/JS，无构建。浏览器会话内保留原始材料和报告。最新简历稿与版式通过同源浏览器存储恢复。模型与提示词可在顶部“设置”配置。新服务独立在 `lib/resume-service.js`，原服务仅路由委托。

真实模式优先使用本机设置文件，未配置时由 `.env.local` 或环境变量提供 OPENAI_API_KEY、OPENAI_BASE_URL、OPENAI_TEXT_MODEL；仅服务端读取。点击真实 AI 分析才将输入材料发至配置的模型服务。JSON 响应经结构与长度校验，页面始终转义文本。错误不静默降级为模拟结果，不自动重试收费请求。请求有超时、取消与单任务并发限制。无登录、云端保存及生产部署；现有静态托管不能运行新 Node API，本次本地仓库交付不更改既有线上站点。

示例按钮仅填入 4 年 ERP/WMS/经营报表产品经理转 AI 产品经理的合成材料。示例与上传材料均通过同一个真实模型 API 分析；没有本地演示选择器、关键词评分或固定报告回退。追问优化同样调用模型并复用主提示词。风格切换仍为最初用户明确要求的规则模拟，页面保留该标识。

导入使用 mammoth 解析 DOCX（不执行嵌入内容），PDF 文本提取，不做扫描件 OCR；空文本/加密/损坏/超限有明确反馈。导出使用 docx 与 pdfkit 生成真实文件，PDF 使用本机可用的中文字体，字体不可用明确失败。依赖通过精确版本与 lockfile 固定；选择服务端库避免外部 CDN 和将简历传给额外解析服务。解析只接受 PDF/DOCX，限制 8 MB，不保存上传。

## 用户提示词与变量绑定（2026-10-29）

用户提供完整九阶段职业顾问提示词，要求绑定输入变量。本轮将该内容作为默认分析模板；已有本机配置仅更新分析提示词，模型地址、密钥、模型及自定义经历表达提示词保留。模板定义、变量白名单、单次替换和空值处理集中在 `lib/resume-prompts.js`，不改变设置文件 version=1。新变量由可选输入扩展兼容旧客户端，旧请求缺少新字段时使用空值与“不限制”。

| 变量 | 绑定来源 |
| --- | --- |
| `{{role}}` / `{{industry}}` / `{{company}}` | 目标岗位 / 行业 / 公司类型 |
| `{{stage}}` / `{{focus}}` | 求职阶段或经验背景 / 希望突出的能力 |
| `{{jd}}` / `{{resume}}` | 当前 JD / 原始或已导入简历 |
| `{{projects}}` / `{{skills}}` | 代表项目 / 工具与技能 |
| `{{results}}` / `{{boundaries}}` | 有数据结果的经历 / 不希望夸大的边界 |
| `{{length}}` / `{{extra}}` | 一页、两页或不限制 / 其他补充 |
| `{{answers}}` | 经历追问与本人回答，按顺序编号 |

空值显示“未提供（需要补充）”，未回答追问明确“尚未回答追问，需要用户确认”。变量只替换一次，不解释候选人原文中的模板标记。未知、拼写错误或未闭合的变量在设置保存和预览时拒绝。自定义模板未引用的已提交材料通过 additionalContext 补齐，避免删除某个变量后模型丢失该材料。绑定后的材料只进入模型 user 消息，固定事实约束及输出结构在 system 消息；凭证不在变量集合内。模板是用户授权指令，但材料中的指令仍按不可信数据处理。

`POST /api/resume/prompt-preview` 使用相同校验和绑定函数，仅在当前浏览器会话显示结果，不请求模型、不写文件、不写正文日志。关闭设置清除预览；编辑模板或恢复默认使旧预览失效。预览允许必填材料尚未填写，真实分析仍要求目标岗位、JD、简历。
